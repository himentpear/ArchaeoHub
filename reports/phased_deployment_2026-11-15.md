## 已部署流程

| 原始需求 | 当前实现 | 操作入口 |
| --- | --- | --- |
| 单器物切分 | 原页拖框、坐标编辑、多视图、修改与撤回，记录原图哈希和修订版本 | 检索主图 → 单器物精确切分 |
| 比对箭头 | 绘制、移动端点、删除、撤销，跟随图像缩放与镜像，保存在当前浏览器 | 比对台卡片 → 箭头 |
| 线图为主、文字左移 | 左侧文字，右侧大图，线图优先，已确认裁片优先 | 跨卷总索引与检索结果 |
| 正文与图注区分 | 正文描述、图注、表格、脚注、标题及待判定来源标签 | 原句结果与器物证据列表 |
| 重号核查与修改 | 392组关联冲突候选，校订编号、同号消歧、版本检查、修订记录、撤销和导出 | 编号问题，属性、编号与证据 → 校订编号 |
| 模型解耦 | 实体、属性和目录阶段调用独立 HTTP 服务，支持 OpenAI JSON Schema | POST /v1/chat/completions |
| 表格与正文关联 | 按明确标本号绑定行，核对同名尺寸和单位，展示歧义及证据不足 | 结构化表格详情 → 与正文核对 |
| 轻量 Agent 试验 | PAI Agent SDK 0.16.1，独立环境，检索工具与受约束来源配对输出 | 器物卡片 → Agent核查（试验） |

392组记录来自器类、出土信息或属性候选冲突，需要对照原页确认。现有校订作用于器物档案，同一档案内已经合并的多件器物仍需拆分功能。

## 实机验收

- 完整测试通过120项，用时55.78秒。前端 JavaScript 语法检查和 `git diff --check` 通过。
- 三个本地服务返回健康状态。标准 `json_schema` 请求返回符合约束的 JSON，未知模型名返回404，非法消息结构返回400。
- 实体抽取通过独立本地模型 API 完成，返回“宋代”“青白釉”“碗”及逐字原文位置。
- 在暂存库保存 `T20D2∶314` 的单件线图裁片，原页坐标为 `[654,1135,196,60]`。保存后检索主图切换为该裁片，导出保留区域信息。
- 在暂存库通过界面保存并撤销同号消歧，生成两个修订版本。正式库的编号修订与人工裁片数量均为0。
- 比对箭头已验证绘制、镜像、缩放与刷新恢复，验收添加的比对卡片已清理。
- 《观台磁州窑址》物理页535生成2张候选表、103个单元格，单页处理约61.89秒。该页为探方和钱币统计，识别结果未出现可绑定的标本号，核对界面显示证据不足。尺寸冲突、单位换算、修正后重新比较及多器号歧义通过回归测试。
- PAI Agent 界面任务完成，用时83.64秒，实际调用1次检索工具并返回6处证据。引用可跳转到相应卷次原页，已验证第五卷印刷页775。任务绑定器物档案，运行结束前复核页面和编号版本。

Agent试跑存在误报，例如把同件炉的正文与图注配对为“器类差异”，以及把残高与通高放入尺寸差异候选。当前输出保留“待核查”状态，来源配对与语义判断需要人工复核。

运行证据保存在 `data/processed/services/`、正式库的 `agent_runs/` 和 `data/processed/benchmarks/deployment-tables-20261114/`。

## 后续流程

1. 自动视觉定位与分割。以原页人工裁框建立标注样本，比较 GroundingDINO 的候选定位及 SAM2 的轮廓分割，覆盖多器物、多视图和残片图页，再接入现有区域审校流程。
2. OCR模型对照。保留同页、同区域及0、90、180、270度输入，比较现有识别流程与 PaddleOCR-VL、MinerU 候选，分别统计标本号、单元格文字、行列结构及单位准确率。本轮沿用现有识别器。
3. 器物档案拆分。支持在同一卷内将已合并记录的具体出处、属性证据与裁片分配给不同器物，保留修订与回溯关系。
4. 标签与 Agent 评测。独立标注正文、图注及真实冲突样本，评估标签分类和来源配对误报，再调整模型与提示词。
